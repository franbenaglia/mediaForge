# Development guide

How to build MediaForge, test it, publish it and keep it going (main.md §17). The design documents ([ARCHITECTURE.md](ARCHITECTURE.md), [DECISIONS.md](DECISIONS.md)) are in Spanish; this guide is the entry point.

## 1. Environment

| Tool | Version |
|---|---|
| JDK | 17 |
| Android SDK | platform 37, build-tools 37 |
| Gradle | 9.8.1, through `./gradlew` (don't use a system Gradle) |
| Android Gradle Plugin | 9.4.1 |
| Kotlin | 2.4.21 |

```bash
git clone https://github.com/franbenaglia/mediaForge.git
cd mediaForge
echo "sdk.dir=$HOME/Android/Sdk" > local.properties
```

`gradle.properties` caps Gradle at 2 workers with small heaps, because the project was developed on a machine with 15 GB of RAM. On a bigger machine you can raise them, but don't commit that change.

## 2. Build

| Variant | Command | What it is |
|---|---|---|
| `debug` | `./gradlew assembleDebug` | Development; package `com.fabapps.mediaforge.debug`. |
| `minified` | `./gradlew assembleMinified` | Same R8 code as release, signed with the debug key; package `.minified`, shows up as "MediaForge R8". Use it to test R8 on a phone without the release key. |
| `release` | `./scripts/build-release.sh` | Signed APKs plus `SHA256SUMS` (see [RELEASE.md](RELEASE.md)). |

There's one APK per ABI (`arm64-v8a`, `x86_64`), because the native engines take ~50 MB per architecture (ADR-004).

## 3. Tests

```bash
./scripts/verify.sh                 # mandatory before every commit: build, unit tests, lint, ktlint
./gradlew ktlintFormat              # fixes formatting
./scripts/test-device.sh            # instrumented tests on a physical phone
./scripts/test-device.sh --offline  # same, skipping tests annotated @RequiresNetwork
```

- **Unit tests** run on the JVM with no network or device. The engines are replaced by small `sh` scripts that imitate yt-dlp and FFmpeg.
- **Device tests** check the real engine, the converter, MediaStore and the app UI.
  - Use a physical phone: the emulator was too heavy for the development machine.
  - The script installs the debug app as an update and leaves it installed, so the phone keeps its data.
  - On Xiaomi/HyperOS, grant the app "Display pop-up windows while running in the background", or the UI tests hang.
- **Test files** are generated by FFmpeg (`lavfi`), or are trimmed yt-dlp outputs. Each fixture folder has a README with its origin.

## 4. Architecture in one minute

| Module | Contents |
|---|---|
| `core/domain` | Pure Kotlin: models, engine contracts, the job queue (`JobScheduler`), conversion planning, file names, URL validation. No Android. |
| `core/media` | Adapters: yt-dlp (`YtDlpExtractor`, `YtDlpDownloader`, `YtDlpUpdater`), FFmpeg (`FfmpegConverter`, `FfmpegCommand`), process runner, MediaStore. |
| `core/data` | Room (jobs, history) and DataStore (settings). |
| `app` | Compose UI, ViewModels, foreground service, notifications, sharing, Hilt. |

Commands are always argument lists, and URLs always go after `--` (see [SECURITY.md](SECURITY.md)). More in [ARCHITECTURE.md](ARCHITECTURE.md).

## 5. Updating yt-dlp

- **Users get it automatically.**
  - `EngineAutoUpdate` checks GitHub at most once a week. It installs a new release only if `SHA2-256SUMS` is signed by yt-dlp's key and the file matches it (ADR-022).
  - The key is pinned in `core/media/.../update/YtDlpSigningKey.kt` by its fingerprint.
  - If yt-dlp ever rotates its key, replace the armored key and the fingerprint there. Verify the new key against the one published in yt-dlp's repository before changing it.
- **The bundled copy** (`res/raw/ytdlp` in youtubedl-android) is only the starting point. To refresh it, update youtubedl-android (next section).

## 6. Updating FFmpeg, Python and the bundled yt-dlp

All three come from [youtubedl-android](https://github.com/yausername/youtubedl-android), which packages Termux builds (ADR-001, ADR-002). To move to a new version:

1. **Bump the library.** Change `youtubedlAndroid` in `gradle/libs.versions.toml`.
2. **Retest the engine on a phone:**
   - `./scripts/test-device.sh`: engine, converter, cancelling;
   - `./gradlew assembleMinified`: check R8 with a fresh install of the `minified` variant.
3. **Update the license material:**
   - Find the Termux snapshot the new version used. Compare the versions printed in the binaries with the version history of `termux/termux-packages`; ADR-023 explains how.
   - Update `distribution/gpl-sources.tsv` and `notice-sources.tsv` with the versions, URLs and SHA-256 from that snapshot's recipes, and change the snapshot commit in `scripts/package-gpl-sources.sh`.
   - Run `./scripts/build-notices.sh` and commit the new `app/src/main/assets/third_party_notices.txt`.
   - Update [LICENSES.md](LICENSES.md).
4. **Note it** in `CHANGELOG.md`.

To build FFmpeg or Python yourself instead, follow `BUILD_FFMPEG.md` and `BUILD_PYTHON.md` in youtubedl-android. That uses `termux-packages` and Docker.

## 7. Releasing

See [RELEASE.md](RELEASE.md). In short:

1. `./scripts/build-release.sh` builds the signed APKs and `SHA256SUMS`.
2. `./scripts/package-gpl-sources.sh <version>` builds the corresponding-source archive.
3. Test on a phone with a fresh install.
4. Create the tag and the GitHub Release with the APKs, `SHA256SUMS`, the sources archive and the changelog section.

## 8. Continuing development

The project was built in stages, with a small harness that lets work resume from the repository alone:

- `CLAUDE.md`: rules that aren't negotiable, and the quality gate for each task.
- `harness/STATE.md`: current stage, last verification, blockers, known problems.
- `harness/TASKS.md`: tasks with acceptance criteria. `[~]` means done but not yet validated on a phone.
- `harness/SESSION_LOG.md`: one entry per work session.
- `docs/DECISIONS.md`: ADRs. Read the relevant one before changing a decision.

Commits are small and named `T<id>: <summary>`, without mixing features, fixes and refactors. A task is done when `verify.sh` passes, its acceptance criterion is met (on a phone if needed) and the affected docs are updated.

Rules that hold in every change: no DRM bypass, login evasion or watermark removal; no string-built commands; no executing downloaded code without checking its signature and hash; file names always through `FileNames`; UI text in resources (English and Spanish); no analytics, ads or Google Play Services.
